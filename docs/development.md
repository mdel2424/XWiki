# Developing XWiki

See the [main README](../README.md) for the app demo and feature overview, and the [pipeline notes](pipeline.md) for archive coverage and ranking details.

## Preview locally

Node.js 22 or later is sufficient to serve the bundled site:

```sh
npm start
# http://localhost:4173/
```

The application is served from the repository root. No dependency installation or database is needed for this preview. To open it from a phone on the same trusted Wi-Fi network:

```sh
HOST=0.0.0.0 npm start
# Open http://<this computer's LAN IP>:4173/ on the phone.
```

## Build

Use the committed catalogue to assemble the deployable site:

```sh
npm run build -- --reuse-data
npm run preview
```

The build copies `index.html`, `site.webmanifest`, `style.css`, `src/`, `images/`, and `data/` into `dist/` and adds `.nojekyll`. The bundled export contains 201,844 articles and 697,007 HN mentions, about 613 MB of published files. The build enforces a 950 MB budget. `dist/` and the local database are ignored by Git.

With an imported archive at `.data/wikihack.sqlite`, `npm run build` exports fresh data before assembling the site. Use `--reuse-data` for UI changes and builds that should retain the existing snapshot.

## GitHub Pages

In the repository's **Settings → Pages → Build and deployment**, choose **GitHub Actions** as the source. The [Publish GitHub Pages workflow](../.github/workflows/pages.yml) builds and deploys pushes to `main`; it can also be started manually from the Actions tab.

The deployed app is at <https://mdel2424.github.io/XWiki/>. Paths are relative so the site also works under another project subpath or a custom domain. Deployment uses the committed catalogue and needs no Python environment or application server.

## Data preparation

Python 3.10 or later, SQLite FTS5, and DuckDB are used for offline data preparation:

```sh
npm run data:setup
npm run data:sync                    # Resumable archive backfill
npm run data:tail                    # New HN IDs, updates, retries and overlap
npm run data:enrich -- --limit 1000
npm run data:export                  # Export to data/catalog/
npm run build -- --reuse-data
```

Commit the updated catalogue along with source changes before deploying. Pull-to-refresh checks for a published snapshot and changes the discovery mix; it does not ingest HN data.

To update ranking indexes from an existing export without the source database:

```sh
npm run data:rank       # Rebuild the six-month Rising ranking
npm run data:weights    # Rebuild discovery weights
```

Additional commands include `data:watch`, `data:status`, `data:audit`, and `data:fill-gaps`. `package:catalog` creates an optional archive for backup or distribution. Full exports include the rankings and discovery weights; exports with `--limit N` are marked partial.

The exporter reads a consistent SQLite snapshot, checks comment offsets, and stages output before replacing the catalogue. If generation fails or exceeds its budget, the existing export is retained. See [pipeline notes](pipeline.md) for gaps, deletion handling, source provenance, and coverage limits.

## Browser data

`data/catalog/manifest.json` points to a versioned snapshot containing article cards, search postings, rankings, ID/redirect lookups, discovery weights, and paginated HN comments. The client fetches shards as needed and keeps a bounded cache.

Recommendations, likes, seen history, and pins stay in the browser. Saved preferences use localStorage. Topic matching checks article titles, descriptions, and Wikipedia categories; mentions in body text alone do not qualify an article. Top and Rising preserve published ranking order regardless of likes. Original HN comment text is escaped before rendering.

The topic picker defaults to alphabetical order. Dragging a handle saves a custom order separately from pin membership; pinned Home tabs follow that custom order. Without a saved order, the Home defaults remain Computer Science, Physics, History. Reordering supports mouse and touch, edge scrolling, and Space/arrow/Enter keyboard controls with Escape to cancel. New topics are appended alphabetically to saved orders.

## Tests

```sh
npm test
# With a project Python environment:
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'

# Browser checks:
npm ci
npx playwright install firefox
npm run test:ui
```

The browser suite serves a generated fixture catalogue under a project subpath and checks reading, feedback, topic filtering, pin persistence, loading indicators, navigation, and mobile/desktop layouts. Node and Python tests cover retrieval, recommendation behavior, delayed responses, export integrity, and pagination. Screenshots generated by tests go in the ignored `test-results/` directory; the README uses screenshots of the real catalogue in `docs/screenshots/`.

```text
dist/                         Generated deployment output (ignored)
```
